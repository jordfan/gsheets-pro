gsheets-pro

Google Sheets for Claude Code, built for an agent that can already think.

Thirteen tools it can compose, results it can reason over, refusals that name the fix, and a way to look at what it just built. Every write comes back with an error gate read straight from the API. A lint finds what went wrong and hands back the call that repairs it. A render turns a tab into a PNG so Claude can see its own work.

Nobody else in this landscape verifies, and nobody else renders.

$ claude plugin marketplace add jordfan/gsheets-pro
$ claude plugin install gsheets-pro@gsheets-pro

On a laptop, add gsheets-pro-local@gsheets-pro for the bundled stdio server. Source and issues live at github.com/jordfan/gsheets-pro. MIT.

2

Thirteen tools, shaped like tasks

A capable agent does not need a hundred verbs. It needs a small surface it can compose, results rich enough to reason over, and errors that teach the fix rather than just failing.

So everything here takes sheet names and A1 ranges, and the server resolves the ids and grid ranges. Every response is prose the model reads plus structured data it can branch on. Every error carries a code, a message, and a hint. Every call sends exactly one batch update, backs off on a rate limit, and builds its field mask from the arguments you actually passed.

An agent that can see its own work

This is the part nobody else ships. Every write ends with a masked read over exactly the cells it touched and returns a check keyed on the Sheets error types, so a broken reference is caught by the call that caused it rather than by a person a week later. Because it reads the API's own error enum, it does not care what language the spreadsheet is in.

A1 fx =LET( sheet, sheets_open(url), built, sheets_table(sheets_style(sheet, preset)), filled, sheets_write(built, mode: "fill"), sheets_check(filled) )
  1. 1sheets_open first, always. Never write to a spreadsheet you have not opened this session.
  2. 2Plan before you call. A plan you can state in three sentences produces a sheet someone can read.
  3. 3Build in order: theme, settings, Table, then the formula columns by fill.
  4. 4Read the check on every write. Errors found means stop and fix, not continue and hope.
  5. 5sheets_check before calling it done. Clear every error. Justify any warning you leave.
  6. 6sheets_render once, then look at it. One fix pass, not an open-ended polish loop.

The lint

Seven rules in v1: a formula error, a merge inside a data region, a missing frozen header, a write that landed in somebody else's column, a key column gone blank or duplicated, the sheet's own check column raising a flag, and text that does not read as a colleague's work. Each finding carries the call that fixes it.

The render

A tab becomes a PNG the model actually looks at. Fills, fonts, borders, banding, merges, column widths and conditional formats all paint correctly, and a frozen header repeats on every page. Truncated columns and unreadable contrast are things you can only catch by looking.

What the lint cannot tell you

A clean lint proves your formulas evaluate. It does not prove they are right. An off-by-one range gives you a green check and wrong numbers all the way down. The skill says so in the same paragraph where it tells Claude to run the lint.

A house style it absorbs once

A skill carries ten rules with the reasoning behind each, and a hook injects a short card of it on the first Sheets call of a session. The model learns the conventions once rather than being told them in every prompt.

4

Sheets a person would recognize as their own

Formatting is not decoration here. Each of these is the thing that keeps a spreadsheet correct three months after it was built, which is why they are tools rather than advice.

  • native Tables

    Tabular data is a real Table, not a hand-formatted range. Typed columns, dropdowns, banding and filters come with it, and structured references survive a colleague inserting a row above your formula.

  • themes

    A preset compiles to the spreadsheet's own nine-slot theme, so a color written as a theme slot re-skins when someone changes Format > Theme. Three presets ship. The loader rejects a palette that fails 4.5:1 contrast.

  • settings block

    Every input gets its own cell, a named range, and a note saying where the number came from. A rate typed inside a formula is invisible the day it changes.

  • documentation

    A note on each header cell says what the column means and its units. Validation help text says what a valid entry looks like. Both are written to read as if a colleague left them for another colleague.

  • formulas

    They pass through byte for byte, always. The house style prefers a helper column to a formula nobody can read, XLOOKUP with its missing value argument, IFNA over a blanket IFERROR, and no numeric literal that could ever change.

5

Sharing a spreadsheet with people who never saw your prompt

This is the case that goes wrong quietly. A registry file in your repository names the spreadsheets other people depend on, by id, with no metadata needed anywhere: who owns them, which columns are writable, whether other formulas point at row numbers. Every session on every machine reads it and behaves accordingly.

code "formula_cell" message "D14 currently holds a formula. Writing here would replace it." hint "Read the cell, decide whether you meant to, then pass force."

Formulas are never overwritten

Every write pre-reads the range it is about to touch and refuses if a cell holds a formula, with or without a contract. Getting past it takes an explicit force, which is a decision somebody made rather than an accident.

A dropdown a person built is left alone

Rewriting a validation rule wipes the chip colors somebody set by hand, even when the new condition is byte-identical. That was measured, not assumed, and the colors cannot be restored because the API never exposed them. Rules the plugin did not create are reported as owned by the interface and refused.

Destructive changes ask, or refuse

Deleting a tab or reordering rows needs a confirmation string naming the sheet. On a spreadsheet marked as having positional rows, those are refused outright, because other people's formulas point at row numbers.

Nobody is watching, so it says no

A guard hook asks on a laptop and denies in an unattended run, because an unanswered prompt in a scheduled task just stalls. The denial arrives as the tool's error text with the reason, so the model reads it and reports what it did not do.

6

It runs where Claude Code runs

One server, two transports

The same TypeScript server runs as a stdio process on your laptop and as a stateless HTTP service for cloud sessions and shared hosting. A Dockerfile and a hosting guide come with it, and the tool names key on their suffix, so the same skill and the same hooks work whichever prefix your session hands them.

A vendor command for cloud repositories

A plugin declared in a repository's settings does not install in a cloud run. That was measured, so there is a command that copies the skill, hooks and presets straight into a repository's own configuration directory, where they do load. Commit the result and a scheduled run picks it up.

7

Decided by measurement, not by reading the docs

Six spikes ran against the live API before the design was fixed. Two of them found behavior that silently destroys data, which a naive implementation ships without ever noticing.

  • A Table append that writes an empty row. Appending cells by table id returns success and discards the values you passed. The tool uses the ordinary append against the Table's range instead.
  • A footer color that eats a row of data. Setting a Table's footer color reads like a cosmetic setting. It converts the last data row into a footer and overwrites those cells with sum formulas, silently. Presets never send that field.
  • Two assumptions turned out better than planned. The contract metadata survives Make a copy intact, and the render redirect needs no bearer re-attachment, which removed hand-rolled redirect handling from the design.

801 offline tests run in about a second and need no credentials. A separate live suite runs against a disposable spreadsheet and skips itself when there is not one.

Compared with what else is out there

The Sheets tooling landscape is good at values and rows. It is nearly empty on formatting, and completely empty on verification. Two of these are worth your attention for reasons this project does not cover: the Workspace server below has the best authentication story in the ecosystem and was the closest thing to formatting before this, and Google's own server needs no setup at all.

What it cannot do

Most of these are limits of the Sheets API rather than gaps in this project's coverage of it, and no amount of future work closes them. They are here because you should know them before you install, not after.

  • Named functions and Apps Script are unreachable. Neither has an API. Use a LET inside the formula, or a helper column.
  • Dropdown chip colors cannot be set or read, in either direction. The colored pill in the interface is invisible to every API call.
  • A render never shows a dropdown as a pill. An intact rule created through the API looks pixel for pixel identical to a cell with no rule at all, so the lint is the authority on validation, not the picture.
  • Threaded comments are out of reach. They live in a different API, so a question a colleague left in one is not something the plugin can see. It writes cell notes instead.
  • The export endpoint a render uses is undocumented. It is fenced behind a dedicated tool for exactly that reason, and rendering needs poppler installed on whichever machine runs the server.
  • Setup takes your own Google Cloud OAuth client, about twenty-five minutes the first time. You have to click Publish during setup, or the refresh token expires after seven days and the whole thing quietly stops working.
  • Charts, pivot tables, slicers and filter views go through the raw escape hatch, which reaches them but applies no preset awareness. A chart built that way looks like the Sheets default.
  • The one-call workbook builder and the formula pretty-printer are v1.1. Today a tracker is four calls, and formulas pass through exactly as written.

Install it

Two lines in Claude Code. The first plugin brings the house style, the verify loop conventions, the presets and the guards. On a laptop, add the second for the bundled server that runs over stdio; for a cloud session or a team, run the same server over HTTP and point a connector at it.

$ claude plugin marketplace add jordfan/gsheets-pro
$ claude plugin install gsheets-pro@gsheets-pro
$ claude plugin install gsheets-pro-local@gsheets-pro

This is pre-release and under active development, so it is not installable yet. Watch github.com/jordfan/gsheets-pro for v0.1. A setup command and a doctor command check your token, your scopes, how long your consent screen has been sitting in testing, and whether poppler is installed.
